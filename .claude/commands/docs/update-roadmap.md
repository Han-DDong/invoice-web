# Claude 명령어: Update Roadmap

완료된 작업을 확인하여 `docs/ROADMAP.md`에 ✅로 표시하고 진행 상황을 갱신합니다.

## 사용법

```
/docs:update-roadmap              # 완료된 작업을 자동 감지
/docs:update-roadmap 004 005      # 지정한 Task만 완료 처리
```

인자: $ARGUMENTS

## 프로세스

1. **현재 상태 파악**
   - `docs/ROADMAP.md` 전체 읽기
   - `/tasks/*.md` 작업 파일 읽기 (단계 진행 상황, 수락 기준)
   - `git log --oneline -20`, `git status`로 최근 작업 확인
   - 필요 시 관련 코드 존재 여부 확인 (Glob, Grep)

2. **완료 대상 결정**
   - 인자가 있으면 해당 Task만 대상으로 함
   - 인자가 없으면 아래 근거로 판단:
     - 작업 파일의 모든 구현 단계/수락 기준이 체크되어 있음
     - 명세된 파일과 기능이 코드에 실제로 존재함
     - 관련 커밋이 있음
   - 판단이 불확실한 Task는 임의로 처리하지 말고 사용자에게 확인

3. **ROADMAP.md 갱신** (Edit 사용, 기존 포맷 유지)
   - 개발 단계: Task 제목 끝에 ✅ 추가, `- 완료 ([작업 파일](../tasks/XXX-description.md))` 표기, 하위 항목에 ✅ 표기
   - Phase의 모든 Task가 완료되면 Phase 제목에도 ✅ 추가
   - 작업별 상세 구현 사항: 충족된 완료 기준 `- [ ]` → `- ✅`
   - MVP 체크리스트: 실제로 충족된 항목만 `- [x]`로 변경
   - 예상 개발 일정: 완료된 항목에 ✅ 표시
   - 문서 하단의 `최종 업데이트` 날짜(오늘 날짜)와 `진행 상황` 줄 갱신

4. **불일치 점검**
   - 로드맵과 실제 상태가 다른 부분을 찾아 보고
     - 예: ✅인데 작업 파일이 없는 Task, 모든 Task가 완료됐는데 Phase 제목에 ✅가 없음
     - 예: `진행 상황` 줄이 실제 완료 범위와 다름
   - 불일치는 자동 수정하지 않고 보고한 뒤 수정 여부를 확인

5. **결과 요약 출력**
   - 새로 완료 처리한 Task 목록
   - 변경한 위치 요약
   - 발견한 불일치
   - 다음으로 진행할 우선 Task

## 규칙

- 완료되지 않은 작업에는 절대 ✅를 표시하지 않음
- 작업 파일의 `## 테스트 체크리스트`가 있는 Task는 테스트 통과 여부까지 확인
- 로드맵의 기존 문서 구조와 한국어 문체 유지
- `ROADMAP.md` 외 파일은 수정하지 않음
- 커밋은 하지 않음 (필요 시 `/git:commit` 사용 안내)
